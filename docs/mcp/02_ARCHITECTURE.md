# موصل يقين (MCP): المعمارية والقرارات

## 1. الصورة العامة

```
Claude (أو ChatGPT)                       منصة يقين
──────────────────                        ──────────────────────────────────────────────
مستخدم الشركة يسأل بالعربي
   │  ① يضيف رابط الموصل
   ▼
┌─────────────────┐  ② OAuth 2.1 + PKCE   ┌──────────────────────────┐
│  عميل MCP       │ ─────────────────────▶ │ Supabase Auth (خادم OAuth)│ ← تسجيل الدخول بحساب يقين نفسه
│  (عند Anthropic)│ ◀── رمز وصول للمستخدم ─ └──────────────────────────┘    (بما فيه التحقق الثنائي)
│                 │
│                 │  ③ POST /yaqen-mcp  (JSON-RPC، Bearer)
│                 │ ─────────────────────▶ ┌──────────────────────────┐
└─────────────────┘                        │ Edge Function: yaqen-mcp │
                                           │ ┌──────────────────────┐ │
                                           │ │ mcp_core (البروتوكول، │ │  ④ تحقق الرمز (auth.getUser)
                                           │ │ التحقق من المدخلات،   │ │  ⑤ حد الطلبات + سجل الاستخدام
                                           │ │ الأخطاء، الحدود)      │ │     (service role: هذا فقط)
                                           │ └──────────────────────┘ │
                                           └────────────┬─────────────┘
                                                        │ ⑥ GET /rest/v1/rpc/mcp_*  بنفس رمز المستخدم
                                                        ▼
                                           ┌──────────────────────────┐
                                           │ Postgres: دوال mcp_*      │  ⑦ SECURITY INVOKER
                                           │  ← mcp_guard(): الجلسة    │     ⇒ RLS لكل صف
                                           │    قائمة، الحساب active،   │  ⑧ الشركة = my_company()
                                           │    ليس مسؤول منصة         │     (لا تُقبل من المدخلات)
                                           └──────────────────────────┘
```

**المبدأ:** الموصل **ليس** طريقاً جديداً للبيانات. هو ترجمة من أسئلة Claude إلى دوال قراءة تعمل بهوية المستخدم نفسه، داخل نفس سياسات RLS المختبرة.

## 2. القرارات

| # | القرار | البديل المرفوض | السبب |
|---|---|---|---|
| D1 | منطق كل أداة **دالة SQL من نوع SECURITY INVOKER** (`mcp_*`)، والخادم مجرد ناقل | كتابة الاستعلامات في الخادم بمفتاح service role | الصلاحيات تُطبق في قاعدة البيانات نفسها. خطأ في الخادم لا يكشف بيانات شركة ثانية |
| D2 | **لا يوجد `company_id` ولا `user_id` ولا `role` في مدخلات أي أداة.** الهوية من الرمز فقط | قبول company_id من المستخدم | يمنع التلاعب من الأساس. ومخطط المدخلات يرفض أي حقل إضافي (`additionalProperties: false`) |
| D3 | استدعاء الدوال بـ **GET**، أي معاملة قراءة فقط في PostgREST | POST | حتى لو احتوت دالة على خطأ يكتب، Postgres يرفضه في معاملة READ ONLY |
| D4 | **حماية رمز OAuth على مستوى قاعدة البيانات** (الفجوة G1)، بثلاث طبقات: (أ) دالة `pre_request` ترفض أي طلب غير GET برمز فيه `client_id`، (ب) سياسات restrictive على كل جداول الأعمال وعلى storage تمنع الكتابة لرموز OAuth، (ج) الدوال الكاتبة SECURITY DEFINER تفحص `forbid_oauth()` | الاعتماد على أن Claude لن يستخدم الرمز للكتابة | الحماية لا تُبنى على حسن تصرف النموذج أو العميل |
| D5 | **التحقق من الجلسة في كل دالة** (`auth.sessions`) | الاعتماد على انتهاء الرمز بعد ساعة | إلغاء الجلسة أو تسجيل الخروج يوقف الموصل فوراً |
| D6 | service role في الخادم **فقط** لـ `mcp_begin` و `mcp_end` (حد الطلبات وسجل الاستخدام) | — | سجل الاستخدام يجب ألا يقدر المستخدم يعدله، والاستدعاء بـ GET لا يقدر يكتب السجل |
| D7 | تنفيذ البروتوكول يدوياً (JSON-RPC 2.0 عبر Streamable HTTP، بدون جلسات SSE) في ملف مستقل بدون اعتماديات | مكتبة MCP SDK | لا يوجد وصول للإنترنت لتثبيت حزم، والكود الصغير المختبر أسهل للمراجعة. **يُعاد تقييمه** عند التطوير |
| D8 | v1 للقراءة فقط، وكل أداة عليها `readOnlyHint: true` | — | شرطك، ومتطلب دليل Claude |
| D9 | مسؤول المنصة **مرفوض** في v1 | السماح له بكل الشركات | يمنع أداة واحدة من جمع بيانات كل العملاء |
| D10 | **الأرقام تُحسب في قاعدة البيانات** وترجع مع `as_of` و `basis` و `complete` و `notes` | ترك الحساب للنموذج | النموذج يعرض ولا يحسب، والناقص يُعلن ولا يُقدّر |
| D11 | النصوص الحرة من المستخدمين (أسماء، ملاحظات) **تُقص** وتُعلَّم بأنها بيانات (`untrusted_text`) | — | تخفيف لحقن التعليمات. **الحماية الحقيقية** أن الأدوات لا تكتب شيئاً |

## 3. المصادقة والهوية

1. Claude يطلب الموصل بدون رمز، فيرد الخادم بـ `401` ومعه `WWW-Authenticate: Bearer resource_metadata=".../.well-known/oauth-protected-resource"`.
2. الخادم يقدّم وثيقة **Protected Resource Metadata** (RFC 9728)، وفيها خادم التفويض = Supabase Auth للمشروع.
3. Claude يسجّل نفسه ديناميكياً لدى Supabase، ويفتح صفحة الدخول. المستخدم يدخل بحساب يقين، ويوافق في صفحة موافقة **تابعة ليقين**.
4. Supabase يُصدر رمز وصول فيه: `sub` (المستخدم)، `session_id`، `client_id` (تطبيق OAuth)، `role=authenticated`.
5. كل طلب: الخادم يتحقق من الرمز عبر `auth.getUser(token)` في GoTrue، ثم يمرره **كما هو** لقاعدة البيانات.

**غير منفذ وغير مختبر** (يحتاج تغيير إعدادات المشروع، وهو ممنوع في هذه المهمة):
- تفعيل خادم OAuth في Supabase.
- صفحة الموافقة.
- التسجيل الديناميكي للعميل.

## 4. الصلاحيات والعزل

| التهديد | الطبقة التي تمنعه |
|---|---|
| قراءة شركة أخرى | RLS على كل جدول، والشركة من `my_company()`، ولا يوجد مُدخل company_id |
| موظف يقرأ قسماً آخر | RLS (القسم من `my_department()`) |
| تمرير هوية مزيفة | الهوية من الرمز الموقّع فقط، والمدخلات الإضافية مرفوضة |
| رمز ملغى أو جلسة منتهية | `mcp_guard()` يفحص `auth.sessions`، و GoTrue يرفض في الخادم |
| حساب معلّق أو موقوف | `my_company()` تشترط `status = 'active'` |
| الكتابة برمز OAuth مسرّب | D4 (ثلاث طبقات) |
| تجاوز RLS بمفتاح إداري | لا يُستخدم service role للقراءة إطلاقاً (D6). مختبر بفحص الكود |

## 5. الاستخدام والحدود والأخطاء

- **`mcp_begin(user, tool)`:**
  - يرفض بعد **30 طلباً في الدقيقة** أو **600 في اليوم** لكل مستخدم.
  - يسجّل في `mcp_usage`: المستخدم، الشركة، الأداة، الوقت.
  - **لا يسجّل المدخلات**، لأنها قد تحتوي نصاً حساساً.
- **`mcp_end(call, ok, ms, rows, error_code)`:** يكمل السجل.
- **حدود المدخلات:**
  - limit ≤ 50.
  - نص البحث ≤ 80 حرفاً.
  - الفترات ≤ 366 يوماً.
  - الأيام ≤ 365.
- **مهلة الاستعلام:** 8 ثوانٍ (إعداد Supabase الحالي لدور authenticated).
- **الأخطاء:**
  - المستخدم يرى رسالة عامة ورمز خطأ (`code`).
  - التفاصيل الفنية لا تخرج إلى Claude.
  - الرمز لا يُسجَّل أبداً.

| حالة الخطأ | رد الخادم |
|---|---|
| بدون رمز، أو رمز غير صالح | HTTP 401 + WWW-Authenticate |
| جلسة ملغاة أو حساب غير مفعّل | خطأ أداة `SESSION_REVOKED` / `ACCOUNT_INACTIVE` |
| تجاوز الحد | خطأ أداة `RATE_LIMITED` |
| مدخلات غير صحيحة | JSON-RPC -32602 |
| أداة غير موجودة | JSON-RPC -32602 |
| انقطاع قاعدة البيانات | خطأ أداة `UPSTREAM_UNAVAILABLE` (يُسجَّل في system_events) |

## 6. فصل التقارير عن MCP (المساعد التنفيذي)

```
① محرك البيانات والحسابات ─ دوال SQL (report_profit_comparison …)  ← المصدر الوحيد للأرقام
        ▲                              ▲
② أدوات MCP (mcp_profit_comparison)    ④ واجهة يقين: "المساعد التنفيذي"
   Claude يسأل ويعرض النص               ← اقتراحات أسئلة ← تحديد الفترات في الكود
                                        ← نفس الدالة ← شاشة تقرير + رسم + تفاصيل السجلات
③ محرك إعداد التقرير = نفس دالة SQL، ترجع JSON منظماً (فترات، قيم، تغير، اكتمال، سجلات)
```

- MCP **لا ينشئ واجهات داخل يقين.** الشاشة التفاعلية تُبنى في واجهة يقين، وتستدعي محرك البيانات مباشرة بصلاحيات المستخدم.
- الاقتراحات الجاهزة تُترجم إلى **معاملات محددة في الكود** (مثل "هذا الشهر مقابل السابق" إلى تواريخ بتوقيت الرياض)، **بدون نموذج لغوي**، فبدون تكلفة وبدون تخمين.
- السؤال الحر يكون عبر Claude نفسه (الموصل).

## 7. التكلفة

| البند | التكلفة | الحالة |
|---|---|---|
| Edge Function للموصل | 0$ ضمن حد الباقة المجانية المعلن | **مجاني، يحتاج تحققاً** بعد التشغيل الفعلي |
| خادم OAuth في Supabase | غير معروف | **يحتاج تحققاً.** الميزة كانت تجريبية |
| الذكاء الاصطناعي | على العميل (اشتراكه في Claude) | مؤكد بطبيعة الموصل |
| الإدراج في دليل Claude | يحتاج اشتراكاً مدفوعاً | **غير منفذ** حسب طلبك |

## 8. مقترح لبيانات الربح (لم يُنفذ، يحتاج قرارك)

لعرض صافي ربح حقيقي يلزم:
1. `invoices.issue_date` (تاريخ الإصدار)، و `invoices.paid_date`، و `invoices.project_id`.
2. جدول مصروفات (expenses: التاريخ، المبلغ، الفئة، المشروع، المورد) أو ربط الفواتير الواردة بفئة.
3. **تعريف محاسبي معتمد** منك أو من المحاسب، مثل: أساس الاستحقاق أو الأساس النقدي، وهل الضريبة داخلة، وكيف تُحتسب الرواتب.

إلى أن يتم ذلك، يعرض التقرير ما يمكن حسابه بدقة، ويصرح بما لا يمكن.
