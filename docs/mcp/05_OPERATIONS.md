# تشغيل موصل يقين: المتطلبات وخطوات التجربة

## المتطلبات قبل أي تشغيل حقيقي (بالترتيب، وكلها تحتاج موافقتك)

1. **نشر ترحيلات التأهيل** (من 01 إلى 08) على الإنتاج حسب `docs/DEPLOYMENT_PLAN.md`. الموصل مبني فوقها.
2. **ترحيل الموصل** `20261109000000_mcp_readonly_connector.sql`. يضيف:
   - دوال قراءة.
   - سجل استخدام.
   - سياسات تمنع كتابة رموز OAuth.
   - خطاف PostgREST: `alter role authenticator set pgrst.db_pre_request`. إذا رفضته Supabase، الأدوات ترفض العمل (`CONFIG_INCOMPLETE`)، ولا تعمل بدون حماية.
3. **تفعيل خادم OAuth 2.1 في Supabase Auth** والتسجيل الديناميكي للعملاء، وصفحة موافقة على نطاق يقين. **هذا تغيير في إعدادات المشروع، ولم يُنفذ.**
4. **نشر الدالة:** `supabase functions deploy yaqen-mcp --no-verify-jwt`.
   - `--no-verify-jwt` لأن الدالة تتحقق بنفسها، ويجب أن ترجع 401 مع WWW-Authenticate.
   - المتغير الاختياري: `MCP_RESOURCE_URL`.

## التكلفة

| البند | الحالة |
|---|---|
| الدالة واستعلامات القراءة | مجانية ضمن حدود الباقة المجانية المعلنة. **يحتاج تحققاً** بعد التشغيل |
| خادم OAuth في Supabase | **غير متحقق** هل هو مجاني ومستقر (كان تجريبياً في آخر توثيق رأيته) |
| الذكاء الاصطناعي | على اشتراك العميل في Claude |
| الإدراج في دليل Claude | يحتاج اشتراكاً مدفوعاً. **غير منفذ** حسب طلبك |
| مراقبة مدفوعة | لا يوجد |

## تجربة الموصل مع Claude ببيانات وهمية (بعد موافقتك)

**التجربة غير ممكنة الآن بدون مخالفة القيود:**
- الباقة المجانية مشغولة بمشروعين.
- تفعيل OAuth على مشروع Yaqen Manage تغيير في إعدادات الإنتاج.

الخيار الأقل خطراً عند موافقتك: **مشروع Supabase مؤقت للتجربة**، ببيانات وهمية فقط. يتطلب إما إيقاف مشروع Forsa مؤقتاً، أو باقة مدفوعة.

**الخطوات:**
1. في المشروع المؤقت طبّق الترحيلات من الأساس حتى الموصل. **لا تطبّق** `staging/supabase_stubs.sql`، فهي للبيئة المحلية فقط.
2. أنشئ شركتين وهميتين ومستخدمين بأقسام مختلفة، ووزّع بيانات `tests/db/30_mcp.sql` نفسها بأسماء وهمية.
3. فعّل OAuth Server والتسجيل الديناميكي، وانشر صفحة الموافقة.
4. انشر `yaqen-mcp`.
5. في Claude (حتى الحساب المجاني يسمح بموصل واحد): الإعدادات ← الموصلات ← **Add custom connector** ← رابط الدالة ← سجّل الدخول بحساب الشركة الوهمية.
6. اسأل: "أعطني ملخص وضع الشركة اليوم"، "ما الفواتير التي تجاوزت 30 يوماً؟"، "قارن نوفمبر بأكتوبر"، ثم كرر بحساب موظف أسطول وتأكد أنه لا يرى الفواتير.
7. شغّل `tests/mcp/mcp.test.mjs` معدّلاً ليستخدم الرابط الحقيقي (خطوة لم تُكتب بعد).

## التشغيل اليومي

| ما تريد | الطريقة |
|---|---|
| معرفة الاستخدام | جدول `mcp_usage` (مدير الشركة يرى شركته فقط)، وفيه الأداة والزمن والنتيجة ورمز الخطأ، **بدون مدخلات** |
| معرفة الأعطال | `system_events` بالمصدر `edge:yaqen-mcp` |
| إيقاف الموصل فوراً | `alter role authenticator reset pgrst.db_pre_request; notify pgrst, 'reload config';`. كل الأدوات ترفض بـ `CONFIG_INCOMPLETE`، وباقي المنصة تعمل |
| إلغاء وصول مستخدم | حذف جلساته (تسجيل خروجه أو إيقاف حسابه). الرفض فوري |
| تعديل الحدود | `mcp_begin`: حالياً 30 في الدقيقة و600 في اليوم |
| التراجع الكامل | `supabase/rollback/20261109000000_mcp_readonly_connector.down.sql` (مختبر) |
