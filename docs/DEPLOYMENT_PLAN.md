# خطة النشر للإنتاج

**لا يُنفَّذ أي شيء هنا قبل موافقتك المكتوبة.** الترتيب مهم: قاعدة البيانات أولاً، ثم دوال الخادم، ثم الواجهة. الواجهة الجديدة تعتمد على الدوال الجديدة، والقديمة تبقى تعمل مع المخطط الجديد إلا في التسجيل (انظر "أثر الانتقال").

## 0. قبل البدء (إلزامي)

1. نسخة احتياطية من الإنتاج بـ `scripts/backup.sh` (مع `INCLUDE_AUTH=1`)، وحفظ الملف ومعه كلمة المرور خارج GitHub.
2. تشغيل CI على الفرع والتأكد أنه أخضر (Postgres 17).
3. يفضّل جداً: تطبيق كل ما يلي على Staging سحابي أولاً، ثم اختبار القبول.
4. فحص التكرارات (M2). إذا رجع أي صف، يُعالج يدوياً قبل الخطوة 1-3:
```sql
select company_id, public.norm_key(plate), count(*) from vehicles where deleted_at is null group by 1,2 having count(*) > 1;
select company_id, public.norm_key(number), count(*) from invoices where kind = 'صادرة' group by 1,2 having count(*) > 1;
select company_id, public.norm_key(number), public.norm_key(party), count(*) from invoices where kind <> 'صادرة' group by 1,2,3 having count(*) > 1;
select company_id, public.norm_key(case_number), count(*) from legal_cases where case_number is not null group by 1,2 having count(*) > 1;
```
   (norm_key تُنشأ في الترحيل 03. قبله استخدم `lower(regexp_replace(x, '\s', '', 'g'))`.)
5. إبلاغ مدراء الشركات: الرموز ستتغير، والموظفون الجدد ينتظرون الموافقة.

## 2. دوال الخادم

1. نشر `yaqen-ai` الجديدة. تحتاج الأسرار: `SUPABASE_SERVICE_ROLE_KEY` (موجود افتراضياً)، و `ANTHROPIC_API_KEY`، واختيارياً `ALLOWED_ORIGINS` و `AI_MODEL` و `AI_PRICE_IN` و `AI_PRICE_OUT`.
2. **لا يُنشر** `whatsapp-webhook` إلا بعد توفر حساب Meta (`WA_VERIFY_TOKEN` و `WA_APP_SECRET`)، ويُنشر مع `--no-verify-jwt`.
3. التراجع: إعادة نشر النسخة السابقة من `git show baseline-pre-hardening:supabase/functions/yaqen-ai/index.ts`.

## 3. الواجهة

1. دمج الفرع في `main` (Pull Request)، فيُنشر GitHub Pages تلقائياً.
2. التراجع: `git revert` لعملية الدمج، أو إعادة الملف من الوسم `baseline-pre-hardening`.

## 4. بعد النشر مباشرة

1. سجّل دخولك، وفعّل التحقق الثنائي لحسابك (مسؤول المنصة).
2. افتح كل شركة وانسخ رمزها الجديد للمدير.
3. جرّب: تسجيل موظف بالرمز ← يظهر "بانتظار الموافقة" ← وافق عليه من شاشة الموظفين.
4. جرّب: حذف سجل ← يظهر في السلة ← استرجعه ← يظهر في سجل التدقيق.
5. اضبط إعدادات Auth: الحد الأدنى 8، و Site URL، وتأكيد البريد بعد SMTP.
6. فعّل النسخ الليلي (سرّا GitHub) وشغّله يدوياً مرة (workflow_dispatch)، وتأكد من نجاحه.

## أثر الانتقال (بين الخطوة 1 والخطوة 3)

يفضّل أن يتم كل شيء في نافذة صيانة قصيرة (أقل من ساعة). خلال هذه الفترة:
- **التسجيل:** الواجهة القديمة ترسل department_id، والخادم الجديد يتجاهله. يُسجل الموظف معلّقاً لكن الواجهة القديمة لا تعرض شاشة الانتظار.
- **الحذف:** يفشل.
- **الترجمة:** لا تُحفظ.
