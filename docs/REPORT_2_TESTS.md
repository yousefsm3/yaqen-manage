# التقرير 2: الاختبارات

كل الأرقام هنا من تشغيل فعلي، والمخرجات الكاملة محفوظة في ملفات `docs/evidence_*.txt`. لم أكتب أي نتيجة لم تُنفَّذ.

## البيئة

| العنصر | الوصف |
|---|---|
| قاعدة البيانات | Postgres 16 محلي (منفذ 54329) فيه نسخة من مخطط الإنتاج. Supabase يُحاكى بـ `staging/supabase_stubs.sql`: الأدوار anon و authenticated و service_role، والدوال auth.uid و auth.jwt، و storage، ومهلة 8 ثوانٍ للمستخدم. |
| انتحال الهوية | كل اختبار صلاحيات ينفذ `SET ROLE authenticated` مع `request.jwt.claims`، وهي نفس طريقة PostgREST في Supabase. |
| الإنتاج | Postgres 17. الـ CI مُعد على Postgres 17، لكنه **لم يُشغَّل بعد**. |
| الواجهة | Chrome حقيقي (Playwright) يحمّل `index.html` كما هو، مع استبدال مكتبة supabase-js بنسخة وهمية تسجل كل طلب. هذا يثبت سلوك الواجهة، **ولا يثبت شيئاً عن خادم Supabase الحقيقي.** |

## التغطية حسب المتطلب

| نوع الاختبار المطلوب | ما نُفذ |
|---|---|
| وحدة | 8 اختبارات لمنطق الخادم، واختبارات لكل دالة جديدة في قاعدة البيانات |
| تكامل | الواجهة مع طبقة Supabase الوهمية، وقاعدة البيانات بهويات حقيقية |
| انحدار | نفس الحزمة قبل وبعد. اختبارات العزل (13) والصلاحيات (6) نجحت في الحالتين |
| أمان | حقن الكود (3 أشكال × كل الشاشات)، وتخمين الرمز، وتزوير created_by والترجمة، وتعديل سجل التدقيق، وتصعيد الصلاحيات |
| أداء | EXPLAIN ANALYZE بهوية المستخدم، و pgbench |
| صلاحيات | موظف وقسم ومدير ومسؤول منصة وزائر، ومعلّق وموقوف، ومدير بدون تحقق ثنائي |
| تعدد الشركات | 13 محاولة اختراق بين شركتين، و "مدير الشركة الكبيرة لا يرى أي فاتورة من 49 شركة أخرى" |
| نسخ واستعادة | استعادة كاملة مع بصمة، ثم تشغيل اختبارات الأمان على النسخة المستعادة (46 نجح، و 4 لم تنطبق لأنها تضيف بيانات موجودة سلفاً في النسخة) |
| قبول على Staging | ⛔ **لم يتم.** يحتاج مشروع Supabase سحابياً منفصلاً، والباقة المجانية ممتلئة (مشروعان). |

## ما لم يُختبر، والسبب

| ما لم يُختبر | السبب |
|---|---|
| دوال الخادم الجديدة (yaqen-ai و whatsapp-webhook) | لا يوجد Deno في بيئة العمل ولا مفتاح ANTHROPIC_API_KEY. اختُبر منطقها المنفصل فقط |
| دقة الذكاء الاصطناعي | لا يوجد مفتاح |
| زمن الاستجابة عبر الشبكة، و Realtime، وتسجيل الصوت على أجهزة حقيقية | لا يوجد Staging سحابي، والشبكة مغلقة في بيئة العمل |
| pg_cron و Postgres 17 | غير متوفرين محلياً. الـ CI مُعد على 17 لكنه لم يُشغَّل |
| التحقق الثنائي مع Supabase Auth الحقيقي | الواجهة مختبرة مع طبقة وهمية، والفرض في قاعدة البيانات مختبر بادعاء aal محاكى |
