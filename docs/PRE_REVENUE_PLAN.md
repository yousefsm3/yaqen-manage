# خطة مرحلة ما قبل العقود (Pre-Revenue)

آخر تحديث: 8 نوفمبر 2026. الأسعار من صفحات منشورة بتاريخ قريب. **تحقق منها قبل الدفع**، لأنها تتغير.

## ما تم تنفيذه في هذه المرحلة (بدون أي تكلفة)

| البند | الحالة | الدليل |
|---|---|---|
| **C2 النسخ الاحتياطي** | مهمة ليلية مجانية على GitHub. كل ليلة تنسخ الإنتاج نسخة مشفرة، ثم **تستعيدها في قاعدة مؤقتة وتتحقق منها تلقائياً**، وتفشل وتبلغك بالإيميل لو اختلف أي شيء. مختبرة على قاعدتين منفصلتين تحاكيان Supabase، وفي CI على Postgres 17 | `evidence_backup_restore.txt`، و CI |
| نسخة عرض للشركات | الواجهة الحقيقية ببيانات وهمية وبدون أي اتصال بالخادم. تعمل كمدير وموظف ومسؤول منصة، وفيها: الموافقة على موظف، والحذف والسلة، وسجل التدقيق، والغرف. الذكاء الاصطناعي والواتساب مكتوب عليهما "غير مفعّل" | `evidence_demo.txt` (17/17)، و `scripts/build_demo.mjs` |
| الإنتاج | **لم يُلمس.** لم يُنشر أي إصلاح، ولم يُشترَ شيء، ولم يُحذف أي مشروع | — |

**ما لم يكتمل في C2:** المهمة الليلية **لا تعمل حتى تضيف سرّين في GitHub** (مجاناً، الخطوات في الأسفل). ولم أختبرها على قاعدة الإنتاج الحقيقية بعد. أول تشغيل بعد إضافة الأسرار هو الاختبار الحقيقي، وأتابعه معك. وملفات الصور والمرفقات (4 ملفات حالياً، تقريباً 5 ميجابايت) غير مشمولة بالنسخ.

## خطوتك الوحيدة لتشغيل النسخ (مجاناً، 5 دقائق)

1. **رابط قاعدة البيانات:** من Supabase ← مشروع Yaqen Manage ← زر **Connect** ← اختر **Session pooler** ← انسخ الرابط واكتب كلمة مرور قاعدة البيانات مكان `[YOUR-PASSWORD]`. لو ما تتذكر كلمة المرور: Project Settings ← Database ← Reset database password. **تنبيه:** إعادة التعيين لا تؤثر على المنصة، لأن المنصة لا تستخدم كلمة المرور هذه.
2. **إضافة السرّين في GitHub:** المستودع yaqen-manage ← Settings ← Secrets and variables ← Actions ← New repository secret، مرتين:
   - الاسم `SUPABASE_DB_URL`، والقيمة الرابط من الخطوة 1.
   - الاسم `BACKUP_PASSPHRASE`، والقيمة كلمة سر طويلة تختارها. **احفظها عندك أيضاً**، لأن النسخة لا تُفتح بدونها.
3. قل لي "أضفت الأسرار"، وأشغّل المهمة يدوياً وأتحقق من نتيجتها.

**ملاحظة:** GitHub يشغّل المهام المجدولة، والتشغيل اليدوي، فقط إذا كان ملف المهمة في الفرع الرئيسي `main`. لذلك أحتاج موافقتك على دمج **ملفات النسخ فقط** في `main`، وهي `.github/workflows/backup.yml` ومجلد `scripts/`. هذا الدمج لا يغيّر المنصة ولا الموقع ولا قاعدة البيانات، لأن ملف `index.html` لا يُلمس.

## 1. ما يعمل مجاناً الآن

| الخدمة | الاستخدام | الحد المهم |
|---|---|---|
| Supabase Free (مشروعان: Forsa و Yaqen Manage) | قاعدة البيانات، والدخول، والملفات، ودوال الخادم | قاعدة 500 ميجابايت (المستخدم الآن تقريباً 6)، وملفات 1 جيجابايت، و**يتوقف المشروع بعد 7 أيام بدون نشاط**، و**بدون نسخ احتياطي من Supabase** |
| GitHub Pages | استضافة الواجهة | يتطلب مستودعاً عاماً على الخطة المجانية |
| GitHub Actions | CI، والنسخ الليلي، واختبار الاستعادة | مجاني للمستودع العام |
| التحقق الثنائي (TOTP) في Supabase | حماية حسابات المدراء | مجاني |
| نسخة العرض (صفحة على Claude) | العرض على الشركات | خاصة بك حتى تشاركها |
| مراقبة التوقف (مثل UptimeRobot) | تنبيه بالإيميل لو توقفت المنصة | يحتاج حساباً مجانياً منك. لم يُفعّل |

النسخ الليلي يتصل بقاعدة البيانات كل يوم. هذا **غالباً** يمنع توقف المشروع بسبب الخمول، لأن المصادر تذكر أن التوقف يحدث بعد 7 أيام بدون طلبات على القاعدة. **لم أتحقق من هذا عملياً، فلا تعتمد عليه.**

## 2. ما لا يمكن تأجيله بأمان

| البند | متى يصير إلزامياً | التكلفة |
|---|---|---|
| تشغيل النسخ الليلي (السرّان) | **الآن.** حتى بيانات التجربة تستحق الحماية | مجاني |
| نشر الإصلاحات الأمنية (بعد موافقتك على خطة النشر) | قبل أن يسجّل أي شخص من شركة حقيقية في المنصة الحقيقية. العرض الحالي لا يحتاجه لأنه منفصل | مجاني |
| تفعيل التحقق الثنائي لحسابك كمسؤول منصة | فور النشر | مجاني |
| عدم توقف المشروع + نسخ يومي مُدار | قبل أول بيانات عميل حقيقية: الباقة المجانية تتوقف بعد الخمول وبدون نسخ مُدار | Supabase Pro |
| بريد لتأكيد الحسابات واستعادة كلمة المرور | قبل أول عميل: بدونه أي شخص يسجل بإيميل غيره | Zoho Mail |
| تقييم قانوني لنقل البيانات واستضافتها، واتفاقية معالجة بيانات مع العميل | قبل استقبال بيانات شخصية حقيقية | أتعاب محامٍ (غير معروفة) |

## 3. ما يمكن تأجيله حتى العقود أو بعدها

- **الذكاء الاصطناعي المدفوع:** المنصة تعمل بدونه. الأزرار تعرض رسالة أنه غير مفعّل.
- **الواتساب وتحويل الصوت لنص.**
- **الاستعادة لأي لحظة (PITR):** 100$ شهرياً، والنسخ اليومي يكفي في البداية.
- **نطاق مخصص لـ Supabase:** 10$ شهرياً، وغير ضروري.
- **تحويل المستودع إلى خاص:** يتطلب GitHub Pro أو استضافة بديلة.
- **الاستضافة داخل السعودية:** بعد التقييم القانوني، كما قررت.

- استضافة داخل السعودية (تكلفتها مجهولة حتى نحدد المزود).

- شهادات أو تدقيق (مثل CCC إن طُلبت منك).
- ضريبة القيمة المضافة.
- فروق العملة.
